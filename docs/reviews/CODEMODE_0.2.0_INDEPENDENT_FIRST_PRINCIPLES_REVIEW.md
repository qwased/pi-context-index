# 0.2.0 独立第一性原理设计评审

- 评审日期：2026-10-29。被评文档标注 2026-10-30；保留其日期，本评审不据此推断实验先后。
- 对象：[0.1.5 使用感受与 0.2.0 重构方向](./CODEMODE_0.1.5_EXPERIENCE_AND_0.2.0_DIRECTION.md)，重点为 §0、§2、§5、§10–§13。
- 性质：独立设计评审，不是实施计划，不修改代码、旧文档、配置或发布状态。
- 证据边界：接受评审委托给出的实测背景事实；核对了原文及有限范围源码，复算了本文算式。未重跑真实会话或模型实验。下文的验收阈值、数据结构和分配规则均为建议，不冒充已实现能力。
- 数据边界：只使用聚合数值与合成例子，不收录真实会话正文、原始会话路径或敏感字段。

## 1. 结论

**不同意将原文直接作为实现契约；同意独立新插件、零模型调用、取消旧格式兼容和放开预算上限的方向。** 新插件的核心应是“保存记录的可校验目录 + 有限展示视图”，而不是另一种声称保全工作意义的摘要。

三项核心问题的裁决如下。

| 核心问题 | 裁决 | 成立条件 |
|---|---|---|
| N 次压缩后定位任意早期工作 | 可以保证记录层面的可枚举、可读取，不能保证任意自然语言问题都在三次检索内解决 | 原始记录或其获授权的归档仍在；身份映射稳定；每轮从源记录重建，而非从上一份选集继承 |
| 不静默丢弃指针 | 必须实现，但原文的集合包含式不足以证明 | 对源记录独立枚举，逐项赋予互斥覆盖状态；正文必须暴露未展示/不可读取的数量及完整清单入口 |
| 两种首消息形态 | 不应靠“识别任务书”分流 | 保留用户原文和结构出处；内嵌长任务书按实际字节付费，外部文件只保留原文已有的路径，不读取、复述或宣称其权威 |

最重要的否定有四项：

1. **时间顺序只证明先后，不证明撤销关系。** “谁推翻谁”属于语义；无显式结构证据时必须交给读者或状态插件，不能由压缩器填写。
2. **行级头尾不是禁令保全方案。** 它避免切断一行，却仍会删除中间整条禁令。只能承诺不切碎已展示的行、其余行有地址，不能承诺禁令不丢。
3. **引用单调性应属于全量目录，不属于可见摘录。** 有限预算不可能让不断增长的可见引用集合永远单调。视图可变，原始地址不得因视图变化而失去。
4. **sidecar 可以加速，但不能创造可靠性。** 删除缓存后仍须得到相同目录和视图；不能把不可重建的编号映射或历史选集只放在缓存里。

6,287→9,588 chars 的扩容值得进入对照实验，但现有证据不能证明净收益为正，更不能证明变更引用会从 1/71 自动升至 71/71。应先改支出顺序，再比较同一分配器的不同预算；不得把分配器重构的收益归因于新增 token。

发布边界接受：新插件可采用 `pi-context-index`，使用独立版本线和 `details.version=3`；旧插件冻结在 0.1.5，旧摘要不迁移、不倒填；删除 legacy 与 `mergeHeaderParts`。新旧压缩插件不得同时安装。本评审不检查包名可用性，也不执行发布。

## 2. 用途与“必须可回答的问题”清单

### 2.1 谁读、读后做什么

主要读者是压缩后继续工作的 agent，次要读者是核对历史的人。读者需要区分三种东西：**看到的原文、目录证明存在但尚未展示的原文、目录也无法提供的内容**。

压缩器回答“记录过什么、依据在哪里”；状态插件独立回答“现在要做什么、做到哪一步”。后一职责不能因没有安装状态插件而自动转嫁给压缩器。没有当前任务来源时，正确结果是继续工作所需信息不足，而不是生成目标或待办。

失败代价按行为区分：

- 错误引用或把旧状态当现状，可能导致错误操作，属于正确性失败。
- 没保住禁令、验收要求或后来的更正，可能造成返工或越权，应重点测量。
- 只有指针但找不到数值，会消耗检索轮次，属于可用性失败。
- 明确暴露未展示区间并返回缺料，不算完整完成任务，但优于凭邻近数字填空。
- 泄露密钥、私人信息，不能用更高召回率抵偿。

### 2.2 必须可回答的问题

以下清单同时是评测问题族，不是新增语义章节。

| 问题 | 产物或 reader 必须给出的答案 | 不允许的替代 |
|---|---|---|
| 这是哪个会话、哪个分支、哪次快照的历史？ | 可校验的来源域与快照标识 | 只有一个无来源的 `#N` |
| 最早还有多早？中间是否还有没展示的记录？ | 目录边界、精确覆盖清单入口及未展示数量 | 用已选引用的最小值冒充历史起点 |
| 此处没写，是历史没有、被隐藏，还是读不了？ | 不同结构状态；“未找到”必须带搜索范围 | 从未展示推断从未发生 |
| 这个数是谁、在什么记录中报告的？ | 值、作用域、原文字段/偏移、对应调用或记录身份 | 用另一版本、另一运行的数字代答 |
| 文件曾收到什么操作请求？ | 记录的操作类型、字面路径、次数和各次来源 | 把工具调用直接叫作磁盘变更或最终文件状态 |
| 某条旧要求原文是什么，后来还有哪些用户发言？ | 可按序完整枚举的用户消息及缺失行地址 | 生成“当前约束”或推测撤销关系 |
| 记录中曾如何表达验收要求、限制或更正？ | 对原文的可定位读取；展示覆盖必须可查 | 从没有对应工具记录推断“尚未验收” |
| `#N` 现在仍指向当初那条记录吗？ | 身份/内容/快照校验结果；失配不返回别条 | 最近编号、相似文本或扫描结果自动顶替 |
| 如何继续读取一个超长记录的命中处？ | 字段和命中偏移、范围页及稳定游标 | 只让读者从记录第一页重新开始 |
| 哪些工具或内容类别没被台账识别？ | 支持范围及未分类记录数量/入口 | 声称 Files 等于全部真实文件变化 |
| 文件路径指向什么？ | 历史中出现的路径及出处；文件现内容由文件工具另读 | 压缩器复述文件或替用户指定权威文件 |
| 离开此会话后到哪里找任务？ | 由用户/状态插件持久文件提供；压缩器仅保留已有字面出处 | 让随会话消失的视图成为目标的唯一保存地 |

可验证的定位能力与实际作答能力应分开报告。目录可以证明一条记录可达，却无法强迫模型点击它，也无法保证模型正确解释它。

### 3.2 信息论下界：不可能同时满足的承诺

设一条任务书有 k 条相互独立的二元限制。仅区分所有可能的限制组合，就需要至少 k bit；若要求任意逐字读取，还须保留原文字节或可寻址的外部原文。固定长度视图不可能无损表示任意增长的任务书和任意增长的历史。

这不是反对扩大预算，而是划清预算的功能：

- 增加预算可以买更多**直接可见事实**，降低检索需要；不能把有损选集变成任意历史的无损编码。
- 完整目录把存储成本移到源记录/派生索引，并保留按需读取能力；不是把全部信息免费装入视图。
- 对用户未知的未来问题分布，任何有限摘录算法都存在把关键事实放在未选部分的反例。新增预算的普适收益下界是 **0**；考虑无关内容干扰后，任务收益甚至可能为负。
- “无语义推断 + 有限预算 + 任意禁令直接可见 + 不必读取指针”四者不可兼得。契约必须明确放弃最后两者的普适保证，而非换一种省略标记。

### 3.3 可测的“每 token 换回多少事实”

先在构造产物前冻结事实集合 F 和问题集合 Q。一个事实单位是带作用域的元组，而不是一个数字或一个引用：例如“运行 r 的工具记录报告了计数向量 v”，或“调用 c 使用了操作 o 和路径 p”。同一次运行的 call/result 双引用不能算两项事实；同一计数被抄十遍也只算一项。

定义两个互补指标：

1. **直接证据密度 D**：新增可见、原文校验通过、作用域齐全的不同事实数 / 新增实际 tokenizer token。记录“只给指针”的数量，但不算入直接事实。
2. **使用收益密度 Y(k)**：固定最多 k 次工具调用后，新增“答案正确且引用支持答案”的问题数 / 新增的端到端输入 token。k 取 0、1、3，分别测不点指针、短路径和受限检索。

另报错误断言率、弃答率、找全率、引用精确率、引用读取成功率、每题工具次数及 p95 延迟。把找全率分母固定为可访问真值全集，不能随模型列出多少变化。

这两个指标都能自动测：事实 ID 由源记录身份、字段跨度和作用域组成；答案按预注册字段核对，证据工具验证该跨度确实支持该值。需要人工建立题库真值时，在实验前冻结，不能由模型答案反向挑题。

### 3.4 6,287→9,588 的判断与摊销

增加 3,301 chars，即约 52.51% 的视图容量。即便乐观假设新增 70 个不同操作事实和 7 个不同错误事实都入册且无重复，也只是：

```text
乐观的结构密度 ≈ 77 / 1,050 = 0.0733 项事实/token
                 ≈ 每 13.6 个新增 token 才多一项直接事实
```

这不是实测，更不是期望收益下界；71 的事实口径尚待统一。原文“每一个 token 换回的事实数量级提升”没有完整比较基线，不能成立。

若后面有 15 次带这份视图的模型请求，不计缓存时新增约 15,752 输入 token；不是 18K。若 agent 一轮内有多次模型请求，应按实际请求数 m 求和，而不是按用户轮数乘一次。跨请求累计 token 与一个 450K 窗口相除，不能说明窗口占用或经济占比。

成本与收益的验收式应为：

```text
ΔUtility = Σq wq · [P(正确且有据 | 新视图) − P(正确且有据 | 旧视图)]
ΔCost    = 新旧两条件的实际总费用差
         = 上下文输入费用差 + 检索输入输出费用差 + 额外压缩/延迟成本差
净收益条件：预注册权重下，ΔUtility − λ·ΔCost 的置信下界 > 0
```

缓存命中、冷输入价格和本地端点的时间成本分别记录，不能默认每次全价或一定命中。新增视图约占多大剩余窗口，只能用该请求的实际 token 和实际剩余窗口计算；提前触发的压缩次数必须实测。

**裁决：允许更大上限，但不默认花满。** 用同一新格式在 6,287、8,217、9,588 chars 三档做消融，再加入原生和 0.1.5 作为外部基线。若 8,217 与 9,588 任务收益无差别，采用 needed 截止，而不是用旁白填满新增空间。

## 4. 不变量与可测断言

### 4.1 两层分母，而不是“所有保存消息”和“有效历史”二选一

使用两层账本可以同时防止假缺口与藏缺口。

- **I：身份目录**。固定源快照内所有已分配 `#N` 的消息，包括 system 和废弃分支消息；custom/compaction 不伪造 `#N`，另以宿主 entry ID 记存在性及必要元数据。
- **E：当前视图的有效历史记录身份集合**。按选定分支、context-edit 投影和隐私策略确定，包含 live 尾部，去除 system 等不应进入会话正文的来源；在预算选择和噪声过滤之前冻结。
- **X = I \ E**：不进入本视图的目录项，记结构原因，如 system、off-branch、context-edit-excluded、policy-excluded。X 不算普通展示缺口，但不得从身份目录悄悄消失。

filterNoise 只改变展示资格：例如 `indexOnly(reason=noise-filter)`，不能通过缩小 E 让覆盖指标自动变好。一次源消息投影出多个块时，E 按消息身份去重，块数另计；不能把块数充作消息覆盖数。

旧压缩记录被 context-edit 限制重建时，前缀不属于本轮 E 的部分也应在 I 中登记其范围和原因。`E` 是明确策略的结果，不是 `min(sourceIndices)..max(sourceIndices)` 这个包围盒。

### 4.2 互斥分区与字段级完整性

对 E 中每个身份赋予以下一种消息级状态：

```text
E = Live ⊎ Quoted ⊎ IndexOnly ⊎ Unavailable
```

- Live：本快照的尾部确实提供该记录；不能只凭一个 liveFrom 假定稀疏编号连续。
- Quoted：至少有一个获允许的原文字段跨度在视图中展示；其余字段/跨度仍必须计入未展示清单。
- IndexOnly：有可执行地址，本视图未展示其原文，可进一步区分未选、噪声过滤、长行等原因。
- Unavailable：身份已知，但源缺失、损坏或无法验证。不能给出伪装成可恢复的读取承诺。

`unaccountedCount = |E \ (Live ∪ Quoted ∪ IndexOnly ∪ Unavailable)|` 必须为 0，并单独断言互不相交。不要把正常的 `withheldCount` 或真实的 `unavailableCount` 都命名为 gapCount。

对 Quoted 中每个源字段，再断言：已展示跨度、未展示跨度、策略禁止跨度互不重叠，按允许的源范围完全分区。只引用消息首行不等于覆盖整条 19K 字符消息。

顶部显示各状态计数及完整 `view` 清单入口。碎片很多时，精确区间放在分页清单，不强迫把 O(N) 个区间塞进 O(B) 正文；但顶部必须明确“另有多少记录/跨度未展示”，不能仅写 `saved #0..#M` 就算覆盖完毕。分页 view 必须能枚举到每项，不能只给总数。

### 4.3 不变量表

| 不变量 | 可自动测试的断言 |
|---|---|
| 完整分区 | 用独立源枚举器构造 E；核对互斥并集相等、unaccountedCount=0。故意漏一条/重复一条时测试必须失败 |
| 精确范围 | 生成带 system、分支洞、编辑、噪声的交错序列；展开所有区间后等于登记集合，绝不把 min/max 中的洞认作已展示 |
| 指针不静默消失 | 每个未显示项可经顶部 view 指针和有限分页到达；清单末页显式结束。删掉页或游标续页时校验失败 |
| 身份单调 | 对同一追加式会话，目录 `I_t ⊆ I_(t+1)`，既有 `N→entryId` 不变；摘要选集任意变化不影响它。不可读项保留身份墓碑 |
| 不要求展示单调 | 测试允许 `Shown_t` 不包含于 `Shown_(t+1)`；但已移出显示的项必须转入 live/indexOnly/其他明确状态，不得丢目录地址 |
| 引用可校验 | 所有引用验证来源域、entryId、源跨度和内容摘要；内容/文件身份变动时返回失配，不静默改指向 |
| 原文保真 | 每段摘录严格等于声明字段的 `[start,end)` 子串；模板、插入的闭围栏和观测聚合分别标注为结构产物 |
| 数字有作用域 | 对每项计数校验同一次记录/调用的来源与字段；放入相同数字、不同版本或不同运行的干扰项，不得通过数值相等蒙混 |
| 结构事实不冒充效果 | 工具请求、结果存在、错误标志、报告计数分别核对；`write` 调用本身不能产生“文件已变更”事实 |
| 时间保真 | 正文按源顺序及字段偏移排列；不得因优先级选择而倒置显示，不自动产生 supersedes 或当前状态字段 |
| 预算真实 | 最终渲染的 UTF-16 长度不超过 B；引用、区间、分隔符、围栏修复和来源头全部计费；超长单行也不得越界 |
| 确定性 | 相同完整输入（源前缀、分支、切点、版本、配置、隐私策略、c 和预算参数）重复运行得到相同字节与清单摘要；禁用时钟和缓存命中作为选择依据 |
| 可重建 | 删除/截断/打乱 sidecar 后，从相同源与版本重建，目录、选择跨度、视图文本逐字相同；不使用缓存才能恢复的隐藏状态 |
| 编辑与尾部 | 给定同一源身份的编辑投影，不重复复制 live 的同一跨度；尾部滑出时旧跨度仍在目录，并重新参与本轮选集 |
| 隐私一致 | 被排除内容在 summary、view、scan、read、range、touched、缓存和日志中均不可返回；直接 `read #N` 不得绕过策略 |
| 标记可执行 | 每个渲染出的结构调用交给真实 parser 和 fixture reader 执行；不接受没有 query 的 scan 伪指令 |
| 无摘要自喂 | 历史 compaction 文本和 recall 自回声不成为新叙事候选；它们只按允许的元数据用途处理，跨 100 次压缩仍成立 |

“围栏行数为偶”不是有效围栏断言：混合反引号/波浪号、长度和嵌套文本都可破坏它。应使用实际围栏状态机断言文本结束于闭合状态，结构头与标记均在围栏外。

## 5. 最小数据结构（含 sidecar 取舍）

### 5.1 权威来源与缓存

最小可靠版本不必有 sidecar。应先从 session 源流生成目录和视图，量出性能，再加派生缓存。sidecar 只保存定位偏移、结构事件索引和可复算清单，不存第二份正文、目标或所谓计划。

必须区分“缓存可重建”与“源被删除仍可重建”：后者一般不成立。隐私删除、文件损坏、未保留的父分支原文，会真实减少可读取历史；系统应保留获准的身份墓碑或报告来源未知，不假造可恢复性。

`view` 可以检查“显示/隐藏是否都有登记”，但它必须由**独立全量目录**构造并验证。若 view 只从已选行反推，漏掉的记录连隐藏集合都进不了，写了 view 也不能保证覆盖。

### 5.2 字段级结构

以下是逻辑最小结构；存储可以用共享表和区间编码，避免每行重复。可推导字段不要求全部持久化。

| 结构/字段 | 类型与语义 | 谁使用 | 缺失或失效时表现 |
|---|---|---|---|
| Source.schemaVersion | 固定为 3 | reader、审计器 | 未知版本拒绝按 v3 解释；旧摘要 coverage unknown |
| Source.refSpaceId | 会话/分支引用域标识；不由临时绝对路径充当 | 所有引用解析 | 外部粘贴或分支来源不明时不猜所属会话 |
| Source.snapshot | `{sourceId, sourceEndBytes, prefixDigest, branchHeadId}` | 目录、分页、缓存 | 文件替换/截断或分支改变使游标失效；追加到边界以外不污染旧快照 |
| Source.recipe | `{projectionVersion, extractorVersion, rendererVersion, policyDigest, cut, ctxTokens, blocks, c, capChars}` | 重放、预算审计 | 参数不全只能报告不可精确重放，不用当前默认值冒充历史输入 |
| Entry.identity | `{n, entryId, sourceLocator, sourceDigest}`；n 为会话全局号 | read、range、身份校验 | 重复 ID、损坏行或摘要不符时返回明确失配，禁止自动重编号 |
| Entry.membership | 当前分支/投影成员关系及结构排除原因 | 覆盖分母、默认检索范围 | 分母无法确定时报告 coverage unknown，不打印零缺口 |
| Entry.access | readable / policyExcluded / unavailable 及结构原因 | 所有输出通道 | 禁止内容不可通过另一工具模式读出；不可读不等于空消息 |
| Entry.origin | role、是否宿主 custom 注入；custom 用 entryId 不占 n | 用户时间线、排除配置 | 无机器来源标志的 user 注入按普通 user 处理，明确无法辨认 |
| Span | `{entryId, fieldPath, startUtf16, endUtf16, revisionEntryId?}` | 摘录、命中读取、原文校验 | 字段/版本不匹配则停止读取；不回退到整条第一页 |
| Observation.kind | toolCall / pairedResult / errorFlag / reportedCounter / hostFileOp | 结构台账 | 未支持的工具保留普通工具记录，不假装已识别其文件效果 |
| Observation.sources | 调用、结果和原文跨度组成的来源列表 | 核对值、配对、touched | 缺少配对时只呈现确有记录的一侧 |
| Observation.literal | 字面操作/路径、计数向量原文、工具名；每值都有 source span | 直接作答 | 不合协议的输出保留原文地址，不从邻近文本推导版本或结论 |
| Observation.scope | 记录 ID、toolCallId、可直接证实的运行参数；缺项可为空 | 防止串用计数 | 作用域不全时不得冠以“某版本测试结果”或与其他运行合并 |
| View.id | 对源快照、recipe、选择清单的确定性摘要 | 顶部入口、重放 | 不匹配时拒绝复用旧缓存视图 |
| View.entries | 精确成员及 live/quoted/indexOnly/unavailable 状态，含展示跨度与未展示原因 | 分区验证器、view 分页 | 缺页/漏项为结构错误，不用总数掩盖 |
| View.counts | 从 entries 计算的各分母、各状态数量；unaccountedCount 必须为零 | 顶部和审计 | 存储计数与重算不符即失败；withheld 非零不代表错误 |
| View.cost | `{neededChars, capChars, usedChars, fixedChars}` | 分配器、摊销实验 | 必须能与最终字符串长度复算一致 |
| Cursor | `{viewId, snapshot, mode, nextEntry/field/offset}` | scan/read/range/view 分页 | 模式、策略、源边界变更后拒绝继续；不悄悄换到最新历史 |

不另建 `plan`、`goal`、`preference`、`outstanding`、`currentState`、`authoritativeContract` 数据实体。“用户消息后的第一段助手文本”至多是一个结构位置，不是计划类型。

### 5.3 引用身份：先保住 `#N`，再讨论指纹

当前代码的 `#N` 已按保存文件中计数消息的顺序分配，跨压缩及同文件废弃分支计数，不是窗口序号。见 [global-indices.ts:17–45](../../reference/legacy-0.1.5/src/core/global-indices.ts#L17)。因此原文“fork/retry 后同一位置可能是另一条消息”需要分情形：

1. **同文件追加分支或 retry**：旧记录的编号应保持，主要问题是记录是否仍在当前分支/有效投影中，而不是自然发生位移。
2. **fork 导出成裁剪过的新文件、导入、物理重写或删除**：编号确实可能重排，必须携带原来的身份映射或明确拒绝把旧引用当本地编号。
3. **context-edit 改变有效正文**：编号可能不动，但引用内容与有效投影不同。不能给新文本挂旧 `#N`，让 read 却返回旧原文。

推荐同文件以原始全局序号和 entryId 双键校验；跨文件 fork 若要求旧 `#N` 不变，宿主或新插件必须把继承映射和分配水位保存到**权威会话元数据**，例如不占 `#N` 的持久记录，而非仅放 sidecar。只在发生不能从新文件物理序列推导的继承时需要该额外映射。

父会话已发出的编号不得被子会话的新记录复用；保留已分配水位，排除分支以墓碑登记。并行分支在各自引用域中分配，跨会话引用必须附来源域。若宿主 fork 操作不传这些元数据，这项跨文件承诺就是发布阻断项，不能拿内容哈希假装补上。

对于编辑投影，展示原文跨度应定位到真正存储新文本的 edit entry，并保留目标消息号与 revision 身份。reader 可用 `read #N + revision` 读取；仅有 `read #N` 时仍代表原始保存记录。缺少可寻址投影来源时，不展示投影文本，明确给出结构限制；不得把变换后的文本谎称原文。

**不把 `#N@6hex` 设为强制逐行格式。** 6 hex 是 24 bit，固定错配的偶然漏检概率约为 1/2²⁴；若拿它在候选中搜索身份，503 项至少一次碰撞约 0.75%，10,000 项约 94.9%。后两数是生日碰撞，不能冒充一次固定 ID 校验的失败概率。

推荐内部保留完整摘要和 entryId，工具始终校验；视图只共享一次来源域/快照，引用不必逐个重复短 hash。若产品需要可跨表复制的自含引用，可用足够长的摘要并强制来源域；64 bit 截断在一百万项的生日碰撞约 2.7×10⁻⁸，但对恶意输入仍以完整摘要校验，摘要也不是权限认证。

成本对比：49 处引用追加 `@6hex` 为 343 chars，`@16hex` 为 833 chars，`@64hex` 为 3,185 chars。把完整摘要集中存储比逐行打印更合理。任何指纹都不能恢复被删除内容，不能证明“结论仍有效”，也不能区分内容相同但身份不同的重复消息。

### 5.4 reader 的必要变化

统一保留 scan、read `#N` 分页、range、touched，并增加最小的 view 清单读取能力。下面是新协议的合成示意，不是现有 API 已支持的调用：

```json
{"view":"v7","offset":0,"limit":20}
{"read":42,"field":"toolResult.content[0].text","offset":18600,"length":800,"view":"v7"}
{"range":[0,80],"cursor":"opaque-cursor","view":"v7"}
{"scan":"pass","view":"v7"}
{"touched":"src/example.ts","view":"v7"}
```

scan 应返回命中字段、命中中心片段和能直达该位置的调用，且同一长记录可分页暴露多个命中。read/range/scan 使用同一快照与隐私策略，范围页遇到巨型记录时不能吞掉整页预算而隐去后面的记录。touched 表示“记录中出现的文件操作”，不是当前工作树 diff。

纯 scan 未命中只能说“在指定字段、范围和策略内未找到”，不能证明某项事实不存在。提高默认页宽不是主要修复：一个无边界的大页可能把更多无关内容塞回上下文，仍到不了命中位置。

### 5.5 sidecar 的取舍

| 选择 | 判断 |
|---|---|
| 首版不落 sidecar，流式重建 | 推荐作为正确性基准实现；先测目录构造和分页 p95，再决定是否缓存 |
| 可丢弃的字节偏移/事件索引缓存 | 可接受，缓存键含源前缀、身份域、分支、投影/解析版本及隐私策略 |
| sidecar 存独有的引用身份、曾展示文本或手工修订 | 拒绝；删除缓存就会改变历史或引用语义 |
| 在会话 compaction details 中保存 view 选择跨度和 recipe | 可接受，这是“当时显示了什么”的结构事实，不是当前状态；旧版本 renderer 或稳定渲染规范须可获得 |
| `cited` 与 `shown` 两集合 | 不足；还需独立全集、排除原因、可读性与字段未展示跨度。仅两集合会遗漏从未 cited 的记录 |
| 与 session 同目录同权限 | 只是必要条件之一；还需禁止正文复制、禁止额外遥测、处理 ACL/备份同步及可识别的路径元数据 |

缓存损坏时重建，不改变选集；源损坏时停在可验证边界并报告不可读，不以猜测修补。策略变严格后的重放可以依法减少可见内容，此时不能再声称“输入相同”：policyDigest 已不同。

## 6. 预算分配公式与四档算例

### 6.1 预算单位与天花板

接受随规模增长至 4,000 token 的上限，不回退到固定 2,000 上限。作为首轮实验基线保留委托公式，但把量纲、取整和输入时刻写清：

```text
C(ctx) = min(4000, 2000 + 0.005 × max(0, ctx − 200000))       // token 额度
T      = clamp(15 × blocks, 1100, C(ctx))                    // token 额度
Bcap   = floor(T × c)                                       // UTF-16 chars
B      = min(Bcap, neededChars)
```

- ctx 是本次压缩输入的固定宿主计量，不是重放时从摘要估出来的新数。
- c 是固定到 recipe 的 charsPerToken；它只用于分配，真实模型费用另用实际 tokenizer 计量。
- blocks 定义为允许进入本视图的有效内容在展示噪声过滤前的结构块数；custom 跳过策略、system 等排除项不涨预算。消息数、投影块数分开记录。
- 使用 floor 保证字符上限；最终 UTF-16 长度仍须实测。采用 round 也可以，但必须统一契约，不能混用。
- 该函数是分段线性而非离散台阶，600K 即达到 4,000 上限，不必到 800K。
- `15×blocks` 是增长限制，不是充足性证明。纯工具少块巨输出时即使 ctx 很大，也可能只有 1,100 额度；这应在场景实验中验证。

### 6.2 needed 的确定性定义与花费顺序

不要把一个 token ceiling 与字符 needed 直接取 min。needed 必须是**最终候选渲染成本**，包含所有结构字节，并在 B 尚未决定前确定，防止“预算有多大就生成多少候选”的循环。

本评审建议如下候选优先级，选完后统一按历史顺序输出，不按类别重要性重新排序正文：

1. **H：最小结构封面**。来源/快照、各覆盖状态数量、view 入口。缺内容时才附对应原因，不打印空洞的 395 字符提醒。
2. **U：用户原文**。优先完整保留短消息；长消息优先整段容纳。若 U 全量放得下，不为助手首段或任意配额截掉中间禁令。
3. **EC：结构错误与有作用域的计数证据**。必须是解析协议支持或有完整原文跨度的观测，不靠错误关键词判断状态。
4. **O：文件操作请求等结构记录**。按可识别调用建立行；合并重复记录时保留全部来源列表的可读入口，不把 `x2 (#最后一条)` 当两次都已引用。
5. **A：可选助手原文锚点**。例如各真实用户轮后的首、末助手文本按轮次轮转取完整行，总目标上限固定为 800 chars；它只是结构抽样，不命名为计划，不承诺保全未验证项。

```text
neededChars = cost(H ∪ U ∪ EC ∪ O ∪ A)
```

先按 source identity/field/span 合并精确重复，再计费；同一源跨度仍在 live 时不重复复制。不能因为尾部出现了相同数字、同一文件名或另一轮同样的输出，就删除旧记录的历史身份与作用域。

不足时不删目录：展示单位按整个消息或完整行进入，放不下的行转为 indexOnly，并在 view 中记录确切跨度。短用户消息数量本身超过 B 时，同样必须进入这种处理；“所有用户发言永不折叠”不能作为无限输入保证。

同一优先级的选择使用公开结构顺序：先尝试各消息一个完整单位，再逐轮加深；首尾轮换仅是确定性降级策略，最终仍按 `#N` 排列。不按语义评分、不按关键词找禁令。超长单行若独自超过余额，整行不显示，通过精确地址读取，不按字符切掉否定词。

EC 在 O 前是待测策略而非正确性定理：若消融显示纯操作任务受损，可替换为预注册的结构轮转，但不能在每个样本看过答案后调整优先级。

### 6.3 两种首消息形态如何自动分配

无需识别“任务书”这一语义类型。形态 A 的用户原文字节多，U 自然大；形态 B 的短指令和字面路径字节少，U 自然小。只要路径已在原文里，不再另付 80 chars 生成 `task contract: authoritative`。

外部文件可以变化，因此本轮读取它不是压缩器的工作。压缩器保留路径当时的字面拼写和来源；若历史中恰有一个读取工具结果，记录那次读取的出处，但不将文件全文提升成优先摘要副本。

从给定样本做一个有启发性但非新测量的替换：

```text
旧脊线             8,217
减强制助手首段    −1,312
把用户 1,020 改为 2,478 的原文预算：+1,458
合计               8,363 chars
```

该式仅替换已给出的数值，尚未计入完整用户行的新标签/引用开销，却足以说明：原文的 8,217 不是不可缩减下界；给全部用户原文付费不一定比强制“计划首段”贵很多。

### 6.4 四档复算

以下算例明确用 **c=3.14，blocks=487，向下取整**。这是对公式的算术验证，不是新插件渲染实测。

为两种形态构造公开成本夹具：

| 区块 | A：首消息内嵌长任务书 | B：短指令与文件路径 |
|---|---:|---:|
| H 结构封面 | 200 | 200 |
| U 原文及引用 | 2,600 | 300 |
| EC 错误/计数 | 1,360 | 1,360 |
| O 操作记录 | 3,900 | 3,900 |
| A 可选助手锚点 | 800 | 800 |
| neededChars | **8,860** | **6,560** |

2,600 与 300 是合成夹具的含格式成本，不是对真实样本的重新测量。两形态保持相同工具事实以隔离首消息成本；文件路径已算进 U，不复制文件内容。投影修订引用等额外成本须以真正 renderer 重新测量。

| ctx | C(token) | Bcap(chars) | A：B=min(cap,8860) | B：B=min(cap,6560) |
|---:|---:|---:|---:|---:|
| 200,000 | 2,000 | 6,280 | 6,280 | 6,280 |
| 300,000 | 2,500 | 7,850 | 7,850 | 6,560 |
| 410,000 | 3,050 | 9,577 | 8,860 | 6,560 |
| 500,000 | 3,500 | 10,990 | 8,860 | 6,560 |

对应支出为：

- A/200K：H 200 + U 2,600 + EC 1,360 后，O 最多 2,120，A 不支出；剩余操作仅索引。
- A/300K：前三项相同，O 最多 3,690，A 不支出。
- A/410K、500K：候选 8,860 全部容纳；不用额外空间制造更多旁白。
- B/200K：H+U+EC+O=5,760，A 最多 520。
- B/300K、410K、500K：只需 6,560；长会话不自动吃满 7,850–10,990。

上述“最多”允许因整行粒度留空，最终 usedChars 可以小于 B。

原文数表的复现条件是另一套：从 6,287/2,000 反推 c=3.1435，再 round，才能得到 200K=6,287、300K=7,859、410K=9,588、500K=11,002。若精确 ctx=410,462，此套口径得到约 9,595，而不是 9,588。本文继续用 6,287→9,588 比较用户指定的扩容，但不把它伪称为 c=3.14 的公式输出。

四档要达到 ceiling，blocks 至少分别为 134、167、204、234；未达到时必须按实际 blocks 计算。needed 也不是天然单调：尾部切换、编辑和策略变化都会使它变小。应测试同一候选集下 cap 增加不降低可承载成本，不应要求跨不同历史的文本选集单调。

### 6.5 1,100 与 4,000 两端

以 c=3.14，窄端 cap=3,454 chars，顶端 cap=12,560 chars。

| 端点 | 保留 | 不保留或降为仅索引 |
|---|---|---|
| 1,100，形态 A 夹具 | H 200、U 2,600，EC 最多 654 | 其余 EC、O、A；用户原文比夹具更长时也必须部分仅索引 |
| 1,100，形态 B 夹具 | H 200、U 300、EC 1,360，O 最多 1,594 | 其余 O、A；不为填满空间读取任务书 |
| 4,000，形态 A/B 夹具 | 分别用到 8,860/6,560 | 其余上限不用；不新增任务归纳或语义章节 |
| 4,000，真实需求仍超限 | 同一顺序，目录与未展示声明保持 | 无法容纳的完整展示单位继续仅索引，不宣称全事实直接可见 |

200 chars 的结构封面在窄端占比：c=2 时 9.09%，3.14 时 5.79%，4 时 4.55%，6 时 3.03%。这个比例不证明净收益；它说明值得把封面压到最小可用形式。

最小来源/覆盖入口是履行契约的固定成本，不能为了实验把它永久删除；可比较“紧凑结构头”和“结构头再加长提醒”的任务收益。若 200 chars 无法覆盖真实的大编号和身份字段，应测量真实 H，不能硬截断地址。纯空历史不生成空封面；没有某类缺口就不打印该类提醒。

## 7. 场景矩阵：首消息形态 × 场景 × 处置

A = 首消息本身是长任务书；B = 短指令 + 长任务书文件路径。表中的处理均不增加语义分类。

| 场景 | A 的处置 | B 的处置 | 共同边界与验收 |
|---|---|---|---|
| 多次压缩后的早期工作 | 原始用户各行和历史工具记录一直在目录；显示可变 | 指令、字面路径、过去相关工具记录一直在目录 | 3/10/100 次压缩后旧引用全部可校验，原始记录未丢时均可读取 |
| system/custom/噪声造成编号洞 | 用户原文不受包围盒假覆盖 | 路径原文同样不被洞吞掉 | 双分母、精确稀疏区间；custom 不获假 `#N`，noise 进入 indexOnly |
| 旧禁令后来撤销或缩小范围 | 尽量完整保留两条用户原文及先后，缺行明确 | 保留后来指令，不重新复述文件来覆盖它 | 顺序不产生 supersedes；读者在当前指令与状态来源下解释冲突 |
| 中间行包含禁令 | 优先全量；装不下则显式行范围仅索引 | 不复制文件中间禁令；读者按当前任务来源读取文件 | 将关键禁令随机放到头/中/尾，报告 k=0 与 k=3 遵循率，不能宣称行级头尾全保 |
| 未验证项/验收要求 | 保留原文或精确地址，不转化为待办 | 保留相关发言与文件路径，状态由另一组件供给 | “缺少操作记录”不能推出“尚未验证”；本类题单独评分 |
| 助手结论反转 | 可选锚点按源顺序；新旧记录均可读 | 相同，不把文件现内容当旧结论 | 同一话题先后相反的合成记录，索引不裁决哪个现在正确 |
| 多会话接力 | 由用户或状态插件把获确认任务写入持久文件，压缩器不代写 | 已有文件可以作为接力材料，但是否权威由用户决定 | 新会话没有源会话时，不伪装 `#N` 可读；跨会话引用必须带来源域 |
| fork/retry，同文件追加 | 旧用户引用不变，分支成员关系另记 | 路径引用相同处理 | 不把 off-branch 当失踪；同文件物理序号不改 |
| fork 到裁剪新文件 | 继承编号映射与水位；父源缺失报告不可读 | 同左，文件路径存在不等于历史源存在 | 无持久继承元数据则阻断“跨 fork 稳定”承诺，不在 sidecar 偷存唯一映射 |
| context-edit | 投影原文须指向 edit 来源，原记录不冒充有效要求 | 不因编辑旧摘要而重新导入旧文件复述 | 不复活被排除前缀；默认当前视图与显式原始历史读取区分 |
| 后续几乎全工具 | 用户原文成本固定后，新增预算给可观测记录 | 用户原文短，更多容量给记录 | 完全没有用户消息时 U=0，不捏造目标；无用户切点的尾部安全需宿主集成测试 |
| 纯对话无工具 | U 与助手原文锚点；操作/错误区不生成 | 保留指令/路径与对话，不主动读文件 | EC/O=0，余量不是强制填满；不得保留空工具配额 |
| 单条工具输出数十万字符 | 目录存身份、长度、字段偏移；展示只含有作用域的短证据 | 同左，不复制任务书读取结果作为“摘要” | 索引内存不得随输出复制多份；命中能直达尾部，不靠扩大第一页 |
| 任务书文件后来更新、移动或删除 | 不影响原始用户任务书地址；外部新文件属另一来源 | 路径保持历史字面值；当前读取失败明确报告，不复述旧副本顶替 | 路径指向的当前内容与历史某次读取内容明确分离 |
| 敏感内容 | 敏感行不入任何模型可见视图或缓存摘录 | 路径本身也可能敏感；不得自动打开文件探测 | 通用访问策略覆盖全部 reader 模式；密钥识别不是零漏检保证 |
| 极窄预算 | 不能声称禁令全可见，按完整行降级、目录不丢 | 优先短指令与字面路径，较多记录可见 | 顶部可执行入口不被普通裁剪吞掉；真实 H 计费 |
| 4,000 上限、需求较少 | 达到 needed 即停止 | 更早停止，不复述文件填空 | 额外无关 assistant 文本不应使强制候选消失；需求超限显式隐藏 |
| 删掉/损坏 sidecar | 用户时间线及选集字节不变 | 指令/路径及选集字节不变 | 固定源、recipe、版本后逐字重放；源变更则不是同一输入 |

### 7.1 “谁推翻谁”的不可越界之处

给定两条不相关的指令，“较晚”不表示“撤销较早”；给定较晚一句“按前述条件继续”，“最新优先”甚至必须回读更早文本。因此不能用时间戳或消息号机械地产生撤销边。

只有宿主已保存的结构编辑关系（targetId/revision）可以直接登记，它证明内容被编辑，不证明自然语言要求已被撤销。自然语言中的“撤销上一条”可以逐字保留，但压缩器不解析其作用域。要可靠供给当前目标，应由状态插件或用户维护当前权威文件，压缩器既不读该文件，也不写指向该状态的声明行。

### 7.2 五种“非自愿接触”的明确处置

| 接触机制 | 新设计的处置/不处理声明 |
|---|---|
| 每轮注入进入摘要 | 可识别的 custom 类型由 `skipCustomTypes` 排除展示及派生索引正文；目录仅保留获准的结构计数。不能转为 user 后丢掉来源再过滤 |
| custom_message 不占 `#N` | 不改全局计数规则；custom 以 entryId 登记，不混进数值范围。被排除时不显示其正文；必要的元数据入口不是一个假的用户消息引用 |
| `keep:N` 只数 user | 仍只按宿主可辨识的真实 user 边界处理。若插件用普通 user 注入且没有机器来源标志，压缩器无法分辨，明确不保证 keep 计数不被污染；不靠文本或插件名猜。skip 不偷偷重定义 keep |
| 重复注入污染召回 | 可识别 custom 排除策略同步到所有 reader 模式；普通 user 的精确重复可合并检索展示，但保留全部来源与顺序、且可展开。不能将重复普通 user 从目录删除，也不能宣称它必是注入 |
| 自建写工具没进 Files | 不识别具体插件；只有明确支持的结构调用/宿主 fileOps 才进操作台账，其他记录仍可读。报告支持范围和未分类工具记录，不承诺全部真实文件变化 |

当前原文把这些问题混称为所有路径共有，过于宽泛。源码中的历史重建先筛选 `type=message`，custom_message 不直接进入这条正文路径；旧头部/转换路径与新正文不同。普通 user 注入仍确实可能污染时间线与召回，这一风险不能因 custom 被排除而忽略。

另一个必须修订的现状描述是 `skipCustomTypes` “绝不影响切点”。[before-compact.ts:292–332](../../reference/legacy-0.1.5/src/hooks/before-compact.ts#L292) 中，可渲染性判断使用该配置，并可能触发 compact-all 回退；它并非任何情况下都只影响最后渲染。新插件必须分别测试“用户轮统计不变”和“空前缀处理”，不能把原文一句话当宿主保证。

## 8. 失效模式与反证实验

### 8.1 先固定实验方法

至少按两种首消息形态、工具/对话密度、长输出、编辑/分支、隐私策略建立分层合成夹具，并加入获授权且脱敏的真实样本。每类建议先用 20 个固定种子筛查结构失败；模型实验用同问题的配对重复与随机化条件顺序，区间按会话聚类，不能把同一会话的多题当独立会话。

所有预算条件共享：源快照、尾部、问题、工具、参数、计分器和最大工具次数。设置仅尾部条件；分别测 k=0、1、3 与充分检索条件。冻结题目与候选规则后再生成视图，禁止像“看见失败后手工补一行目标答案”那样把 oracle 条件当一般算法。

以下结构断言必须全部通过；行为改进只有在置信区间与成本门槛达标后才能宣称有效。若单模型或样本量不足，报告点估计及区间，不外推总体概率。

### 8.2 反证矩阵

| 失效模式 | 反证构造 | 验收条件 / 否定什么 |
|---|---|---|
| 读者不点指针 | k=0，答案仅在 indexOnly 中；另设答案直接入册条件 | 前者不能被记为“可直接恢复”；比较准确率、弃答率和无据断言率，不把工具可达当任务成功 |
| 模型对空缺编号 | 给出稀疏 #N 和相邻相似数字，要求读一个不存在的 #N | reader 返回 not-found/非成员，不填补中间号；模型编造引用单独计错 |
| 增大预算被无关内容占满 | 在助手旁白和冗长工具输出里加入大量无关文本，不改变必需事实 | 同一候选契约下，U/EC/O 已可见项不因 A 膨胀消失；若任务收益下降，拒绝默认花满 |
| 删除 sidecar 后视图变化 | 对同一源/recipe 分别使用全缓存、空缓存、截断缓存和乱序缓存 | 原文跨度、覆盖清单和最终字节一致；否则缓存中藏了权威状态，拒绝设计 |
| 时间顺序被误当撤销 | 旧限制、无关新指令、部分放宽、再次收紧交错出现 | 压缩器不生成撤销关系；问答器按真值判断，测遗漏相关原文造成的损失 |
| 行级头尾漏中间禁令 | 将同一关键行放到不同位置，或用一条超长行承载否定条件 | 已展示行逐字；隐藏行有精确地址；k=0 行为变化揭示信息损失，否定“行级头尾保禁令” |
| 未验证项消失 | 验收要求只在中间助手文本，后续有大量操作 | 目录必须可达；在预算下测能否恢复。固定最后一条助手仍失败时，撤回其保全承诺 |
| 决策反转未被看见 | 相同主题先给一结论，后用记录更正，但最后消息是无关话 | 旧新两处都可读、顺序正确；不能只保最后消息便宣称决策恢复 |
| 19K/200K 记录页首陷阱 | 目标分别置于字段尾部，宽词在页首大量出现 | scan 给准确命中偏移，read 一次直达；计数题在三次调用内达到预注册门槛，不只增加页宽 |
| 邻近计数/版本串用 | 两运行共享数字，目标版本没有记录；一项数字只出现在行号 | 台账不得产生目标事实；未知题若答成邻近值即错。只测数字出现无法通过 |
| 假覆盖 | 从目录或清单中间删除一项，仍保留相同 min/max 与总区间 | 独立分区验证器失败；`saved #0..#M` 不能让测试变绿 |
| 引用选集不单调 | 随预算与尾部移动让曾显示的引用退出正文，重复 100 次 | 全量目录引用仍可读且身份不变；不要求可见集合增长 |
| fork/编辑错配 | 同文件 retry、裁剪 fork、新文件同号异文、同文异 ID、编辑投影 | 正确身份才返回；缺继承映射拒绝；编辑原文/投影版本不混同 |
| 秘密经读取旁路泄露 | 在用户、custom、tool、路径、nested 参数、日志中放合成 canary | 所有输出/缓存/调试记录都无 canary；直接 read、旧游标、touched 不能绕过；计数元数据泄露另测 |
| 自回声递归 | 让 recall 返回含引用的长文本，再压缩多次 | 旧 recall 输出不作为新工作证据累积；目录不因自生成内容膨胀假事实 |
| 上下文编辑复活旧摘要 | 编辑旧 compaction、删除一段要求，再做压缩 | 删除的语义章节与前缀不重新进入当前视图；原始归档读取必须显式区分 |
| 预算计量错位 | c=2/3.14/4/6，emoji/组合字/不同围栏/巨型单行/大编号 | 最终 UTF-16 长度守界，页切不破字素，结构头完整；按同一取整规则精确复算 |
| 顶部固定成本无收益 | 同一最小覆盖入口下，增加或减少来源长说明，扫 80–250 chars 真实可行格式 | 保留满足结构契约的最短形式；长说明无收益则删除。不能用字符占比代替行为试验 |
| 摊销不合算 | 同一压缩后回放 1/5/15/50 次模型请求，分别统计有无缓存 | 总任务收益/费用按 §3.4 达标，否则降低 needed 候选而不是关闭覆盖契约 |
| 首消息文件复述过期 | 压缩后修改任务文件，旧文件内容与新内容相反 | 压缩器只给历史指令/路径，不生成权威副本；当前文件读取由读者另做 |
| 工具冒充文件变更 | 自定义工具名似 write，实际无结构 fileOps；另有调用失败 | 只记可证实的请求/结果；unsupported 数量正确，不报“文件已改” |

### 8.3 什么才算证据足以发布

- 结构与隐私性质使用属性测试及宿主集成测试，任何错误引用、隐私旁路、未登记区间都是阻断项。
- “目录完整”必须对照独立源枚举结果，不能拿生成器自己输出的 counts 自证。
- 行为上至少分别报告约束、旧数值、错误定位、验收原文、决策反转、文件指针六类；不得用尾部状态题抵消旧约束的退步。
- 提议扩容验收：相同分配器下，新增预算的端到端净收益置信下界为正，且关键约束与无据断言率在预注册非劣阈值内。达不到就保留更大允许上限、停止默认花满。
- reader 需用真实生产协议复现实验。玩具 scan 的失败说明工具路径有问题，不证明 scan 在结构上不适合作主路径。

## 9. 不同意原文的三点

### 9.1 不同意“时间线 + 行级头尾 = 要求与禁令不会静默消失”

**位置**：原文 §11.2、§11.4、§11.8–§11.10（约 433–511 行）。

**理由**：先后不等于覆盖/撤销；头尾仍丢中间；用户消息都有代表片段不等于所有要求都可见。强制保留每条用户后的第一段助手，又把“这里通常有计划”的经验当成普适事实。

**替代**：用户原文优先完整；不足时只承诺完整行和精确隐藏跨度。所有用户发言可按序枚举；后来的撤销原文也能读到，但不建立推断关系。助手片段只作为非语义、非强制的结构锚点。

**验收**：禁令位置随机化、局部撤销、无关后续指令、助手中段更正四类反例；目录与原文校验零缺失，任务层面分别报 k=0/k=3 结果，不用结构可达率代替遵循率。

### 9.2 不同意“8,217 是必要脊线，扩到 9,588 就能接近全事实覆盖”

**位置**：原文 §0.7、§5.3、§6.4、§12.2–§12.4。

**理由**：8,217 是作者选择的组合成本，包含可删字段；操作/路径/问题分母不一致。1/71 的原因既有选集策略也有预算，不能单因归责。单样本、一次有效四条件调用与定向手补事实，不足以估计未来任务概率或每 token 净收益；算例还混用 c、取整和累计 token。

**替代**：允许原定阶梯上限；用明确计费的 needed 截止，先支付用户原文与可直接核验的结构证据，再买助手锚点；做格式×预算因子实验，真实 token/缓存/请求数全量计费。

**验收**：相同生成器在 6,287/8,217/9,588 三档重放；新增事实和任务收益分别计量。未通过净收益门槛时，不写“接近 71/71”或概率预测。

### 9.3 不同意“短指纹 + 两集合 view + 有效历史包围区间足以保证不丢指针”

**位置**：原文 §5.2 R1/R3、§12.6、§13.3、§13.5。

**理由**：当前 `#N` 不是分支内位置；指纹只检出部分失配，不保留身份。由 cited/shown 得到的 view 对从未 cited 的项没有约束。以过滤后的范围作全集，还能通过改变分母让真实遗漏消失；system/custom 又会带来假洞。

**替代**：独立身份目录 + 有效展示集合双分母，精确互斥分区与字段跨度；来源域/entryId/完整摘要在内部校验；跨文件继承有权威映射；sidecar 可删可重建，不承担独有身份或历史。

**验收**：删除任意目录项能被独立验证器检出；同文件和跨文件 fork 分开测；连续 100 次改变选集不丢旧地址；删除 sidecar 字节级复现；损坏或隐私删除时明确不可读而非伪恢复。

## 11. 未知与风险

### 11.1 本次没有证明的事

1. 尚无新 renderer，8,860/6,560 是合成成本夹具；原文 8,217 也不包含本文全部身份、隐私、投影引用和清单格式成本。
2. 不知道目标模型对“结构封面 + 直接证据”的稳定读取行为，不能保证其不猜数字或必点指针；结构只能保证工具不误返、输出来源可核。
3. 不知道跨文件 fork 是否保留父身份、水位与原文定位。本仓库接口注释不能替代宿主集成证据。
4. 无多轮真实压缩效果、无多模型泛化结论；三个合成压缩用例不是任意 N 的证明，应加属性测试和较长序列。
5. 尚未测量目录流式重建、巨大字段扫描、事件索引和 sidecar 的 CPU/内存/p95；0.1.5 的 28ms 不能继承为新方案性能。
6. 所有未来禁令、验收要求、决策都直接可见的保证不可实现。无语义条件下只能改善成本配置并保持原文可达。
7. 真实文件变更不能仅靠调用日志完整重建；外部进程、自定义工具和失败的写请求使操作台账与磁盘事实不同。
8. 旧记录不迁移不等于不能重新索引旧原始消息。可以按新 reader 读取原始历史，但不能给旧 compaction 倒填 v3 覆盖或复活旧语义摘要。

### 11.2 隐私不是“同目录同权限”一句话

产物应默认遵守源数据访问策略，排除项不得出现在 summary、缓存摘录、命中片段、操作路径、日志或工具回包。可用精确类型/字段/路径规则及上游显式隐私标记实现；这是通用访问控制，不是新增状态插件识别。`skipCustomTypes` 仍是状态插件集成的唯一配置接触点，但不能充当普通用户消息中密钥排除的万能机制。

无法零语义地识别任意私人数据。启发式秘密扫描最多是额外防线，不应承诺零泄露；未获授权的内容不应先复制到索引再尝试删除。内容摘要也可能对低熵秘密造成字典验证或关联风险，应避免向模型/外部日志暴露被排除字段的指纹。

索引删除不等于 session 原文删除，过去已发送给模型的内容也不能收回。隐私排除与“任意早期原文都可读”冲突时，以访问控制优先，并把保证限定为“仍保存且获准读取的历史”。即便只输出被排除条数也可能泄露元信息，严格策略需允许隐藏该层细节，同时报告覆盖口径受策略限制。

### 11.3 逐字原文与禁用断言词的边界

委托禁止产物出现 `done/verified/success`，而原文可能自然含这些词。不能一边承诺任意原文逐字展示，一边承诺这些字面词绝不出现。

本评审按严格字面约束处理：生成视图的模板不得含这些断言词；包含禁用词的原文行不进入压缩视图，登记为输出词法策略导致的 indexOnly，不能偷偷删词后称逐字。原始 reader 在获准读取时返回历史原文，须与压缩产物区别对待；如果同样禁止 reader 返回这些字面词，就必须承认该部分无法逐字读回。

这是纯字面输出约束，不是用于寻找目标/未完成项的意图正则。未来若希望允许历史引用中的这些词，需明确变更这一约束，不能由实现者自行放宽。

### 11.4 确定性与历史重放也有前提

“同一输入字节”应包括源前缀以外的影响因素：投影版本、render 版本、切点、分支、charsPerToken、配置及隐私策略。只有 session 文本相同、其他参数不同，不要求视图字节相同。

历史 view 的复现需要其 recipe 和对应渲染规范；仅在 sidecar 保存旧视图文本再说它可重建，是循环论证。当前视图不能因为缓存里曾出现过某引用就提高它的选择资格。否则删缓存后的变化会变成隐性行为状态。

不对未知编号、缺失字段、损坏源和引用失配使用“最近一个看起来像”的替代结果。安全的降级是明确不可读或范围未知；它不是完整恢复，但比错误证据正确。
